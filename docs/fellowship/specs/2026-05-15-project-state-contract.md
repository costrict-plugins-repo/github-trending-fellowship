# Project State Contract

The canonical shape of `docs/fellowship/` in a Fellowship project, and the lifecycle rules that keep it from drifting.

## Goal

`docs/fellowship/` must hold exactly the project artifacts the Fellowship needs, nothing more. Plugin content stays in the plugin. Completed work moves to archive automatically. The quest-log stays current without depending on user prompts. Drift becomes a hook-detectable bug, not an invisible decay.

---

## Canonical Project Tree

After `/fellowship:start` bootstraps a project, this is the entire allowed shape:

```
docs/fellowship/
├── README.md                  # directory guide (project-owned)
├── product.md                 # what we're building, for whom
├── quest-log.md               # active decisions and commitments
├── quest-log-archive.md       # old quest-log entries (size control)
├── codebase-map.md            # generated by /fellowship:map
├── specs/                     # active specs
├── plans/                     # active plans
├── handoffs/                  # active companion-to-companion briefs
├── design/                    # active design artifacts (mockups, etc.)
├── research/                  # model/landscape research briefs that inform routing decisions
└── archive/                   # graveyard (flat, see below)
    ├── specs/
    ├── plans/
    ├── handoffs/
    └── design/
```

Nothing else is permitted at the top level. Files appearing outside this shape are drift and the SessionEnd hook flags them.

(Amended 2026-06-11: `research/` admitted to the canonical tree — model/landscape research briefs that inform routing decisions. Optional like `ethos-overrides.md`: not created by the `/fellowship:start` scaffold, present only when research work exists. Research briefs carry `status: reference` and do not enter the implemented/reviewed/archived lifecycle.)

(Amended 2026-06-11, second: `debug-log.md` admitted as an optional top-level file. Three live contracts create it — Gimli's debug-log discipline, the investigate skill, and `using-fellowship` — and the `session-start` hook ingests it; it was absent from the canonical set only because no project had appended to it yet. Optional: not scaffolded, no lifecycle.)

### Removed from current shape

- **`session-log.md`** — killed. Git log records what changed; quest-log records decisions. Session attendance is a metric without a question behind it.
- **`templates/`** (when containing plugin reference content like `ethos.md`) — never created in user projects. Plugin content stays in the plugin.
- **`research.md`, `reference-implementations.md`, `examples/`** — dogfood-only, exists in this repo because this repo *is* the plugin. Other projects must not have them.

## Plugin-Owned vs Project-Owned

| Content | Lives in | Editable by user? |
|---|---|---|
| Ethos (Fellowship Principles) | `skills/using-fellowship/references/ethos.md` (plugin) | no — read-only reference |
| Companion agent files | `agents/*.md` (plugin) | no — plugin content |
| Skill references | `skills/*/references/*.md` (plugin) | no — plugin content |
| Workflow templates | `skills/using-fellowship/references/workflows.md` (plugin; single file with documented split trigger at >5 recipes or >200 lines per recipe — landed 2026-05-24) | no — plugin content |
| Project ethos overrides | `docs/fellowship/ethos-overrides.md` (project, optional) | yes — only if user opts in |
| Specs, plans, quest-log, product.md, handoffs, design | `docs/fellowship/` (project) | yes — these belong to the project |

The principle: anything the Fellowship *teaches* lives in the plugin. Anything the project *decides* or *plans* lives in the project. The bug we're fixing is plugin teaching leaking into project trees.

## File Naming Convention

Every artifact in `specs/`, `plans/`, `handoffs/`, `design/`, and any future first-class artifact folder follows a single naming shape:

```
YYYY-MM-DD-<kebab-slug>.md
```

**Two rules:**

- **Date prefix is mandatory.** Chronological sort across a flat folder of markdown beats every other indexing scheme. The date is the artifact's creation date (taken from `created:` in frontmatter; if absent, from git log of the file's first commit).
- **Slug is descriptive, not encoded.** Type indicators (`adr-`, `spec-`, `comparison-`), author names (`merry-`, `gandalf-`), and status markers do NOT belong in the filename. That information lives in frontmatter (`type:`, `author:`, `status:`). The filename answers exactly *when* and *what*, nothing else.

**Examples:**

```
specs/2026-05-15-project-state-contract.md
specs/2026-04-22-adr-legolas-structural-review.md     # adr is the slug, not a type prefix
plans/2026-04-22-p4-p5-p6-plan.md
handoffs/2026-04-26-gandalf-to-gimli-todowrite-blocker.md
design/2026-05-15-onboarding-wireframe.md
```

**Handoffs note.** The slug for a handoff can encode `from-to-<topic>` (e.g., `gandalf-to-gimli-auth-cleanup`) because that *is* the content. It is still the slug, not a separate field — the date prefix still leads.

**Enforcement, three levers:**

1. This contract section is the source of truth.
2. `/fellowship:reconcile` auto-renames mis-named files: reads the date from frontmatter `created:` or from `git log`'s first-commit date, prepends to filename, slug-cases the rest.
3. Companion contracts (Aragorn for specs, Merry for ADRs, planning skill for plans, others for their artifact types) carry the convention as part of their write protocol. A companion creating a file with a non-conforming name is a contract violation, caught by the SessionStart drift check and corrected by reconcile.

## Status Frontmatter (load-bearing)

Every spec, plan, handoff, and design artifact carries this frontmatter:

```yaml
---
name: <kebab-case-slug>
status: active | implemented | reviewed | archived
created: YYYY-MM-DD
author: <companion-name>             # set on creation by the producing companion (Aragorn, Merry, Arwen, Pippin)
type: <design-spec | adr | prd | plan | handoff | design-contract>   # optional, scopes the artifact
implemented_by: <companion-name>     # set when status → implemented
reviewed_by: <companion-name>        # set when status → reviewed
---
```

**Lifecycle transitions** (each is set by a specific companion as part of their DONE protocol):

| Transition | Set by | When |
|---|---|---|
| `active` → `implemented` | Gimli | Before reporting DONE on the work this artifact describes |
| `implemented` → `reviewed` | Legolas | On review-pass (APPROVED) |
| `reviewed` → `archived` | SessionEnd hook | At session close, sweep all `reviewed` artifacts into `archive/<type>/` |

**Handoffs** follow the same lifecycle. A handoff goes `active` → `implemented` when the receiving companion has consumed it, and `implemented` → `reviewed` when the review for that work passes.

## Discipline: How the Status Markers Actually Get Set

The quest-log went stale because nothing forced updates. This contract fails the same way unless companions are bound to the protocol. Two reinforcing levers:

### Lever 1 — Hard contract in each companion agent file

The DONE protocol for **Gimli** must include, non-negotiably:

> Before reporting DONE on any work, you set `status: implemented` and `implemented_by: gimli` in the frontmatter of the spec or plan that described the work. A DONE report without this step is incomplete. If no spec or plan exists for the work, name that fact in the report.

The APPROVED protocol for **Legolas** must include, non-negotiably:

> When you approve work, you set `status: reviewed` and `reviewed_by: legolas` in the frontmatter of the spec or plan the work was reviewed against. An APPROVED report without this step is incomplete.

Other companions that produce or consume artifacts (Aragorn for requirements, Merry for ADRs, Arwen for design contracts, Pippin for test artifacts) carry the same contract scoped to their artifact type.

### Lever 2 — SessionEnd auto-reconciliation

The SessionEnd hook reconciles status drift without asking the user. Housekeeping is automated, not interactive.

1. Survey the session: any companion reports of DONE / APPROVED?
2. For each, check the relevant spec/plan/handoff frontmatter.
3. If a transition was missed (e.g., Gimli reported DONE but the spec is still `active`), Gandalf sets the correct status based on the report. No user prompt.
4. Log the auto-correction to a plugin-internal trace (for diagnostics — companion contract violations are a plugin-improvement signal, not a user concern).

Then the archival sweep, fully automatic:

5. Find all artifacts with `status: reviewed`.
6. Move each to `archive/<type>/`.
7. Print one summary line at session close: *"Archived 3 specs, 1 plan, 2 handoffs to `archive/`."*

The summary line is the *only* user-facing output. No prompts, no confirmations. Silent file moves erode trust; transparent automatic moves do not.

## Quest-Log Auto-Update

Quest-log entries (decisions and commitments that survive across sessions) get written by the companion that made the decision, appended by Gandalf as scribe.

### Mechanism

Every companion's structured report includes an optional one-line field:

```
quest-log-entry: <one-line decision or commitment, dated implicitly>
```

If the field is non-empty, Gandalf appends it to `quest-log.md` as part of consuming the report, prefixed with today's date and the source companion:

```markdown
- [ ] **<entry text>** (<companion>, YYYY-MM-DD)
```

Companions are instructed (in their agent files) to populate this field whenever they:

- Make an architectural or product decision that will outlive the session
- Take on a commitment that future sessions need to know about
- Identify a deferred concern that mustn't be lost

**Backstop:** Gandalf reviews the session at end-of-session for decisions made in conversation (not via companion dispatch) and appends them directly. Candidate entries surface in the SessionEnd summary line so the user sees what was logged. No prompt. If Gandalf mis-classified casual chat as a decision, the user removes the line in the next session — but the default is to log, not to ask.

### Quest-Log Size Control

When `quest-log.md` exceeds 50 entries, the oldest 25 are moved to `quest-log-archive.md` as part of the SessionEnd archival sweep. No prompt needed — quest-log-archive.md is permanent project memory by design.

## Archive Folder Shape

Flat, one folder per artifact type:

```
docs/fellowship/archive/
├── specs/
├── plans/
├── handoffs/
└── design/
```

No quarterly or yearly subdivision. Chronology is preserved at the entry level (each artifact has a `created:` date in frontmatter; the file's git history carries the rest).

**Compaction:** When `archive/` grows uncomfortably large (subjective; revisit at 100+ files), a future `/fellowship:compact` skill summarizes old entries into a single retrospective markdown file per type, then deletes the originals in a normal commit. Git history retains them.

**Archive stays in git.** The archive is the project's long memory. New contributors, future sessions, and "why did we do it this way?" questions depend on it persisting across clones.

The bootstrap command must be updated to match this contract. Specifically:

1. **Stop creating `templates/ethos.md`** inside the user's project. Ethos lives in `skills/using-fellowship/references/ethos.md` (plugin) and is loaded on demand.
2. **Stop creating any `templates/` directory** in user projects.
3. **Create `handoffs/` and `archive/`** as part of the initial scaffold.
4. **Create `archive/specs/`, `archive/plans/`, `archive/handoffs/`, `archive/design/`** as empty placeholders (with `.gitkeep` if needed).
5. **Do not create `session-log.md`**.

## SessionStart Drift Check

Beyond the SessionEnd sweep, a dedicated SessionStart hook performs a one-shot drift check. **Hook strategy:** new file `hooks/fellowship-drift-check-session-start.mjs`, registered in `hooks.json` after the existing `fellowship-opener-session-start` entry. One hook, one job — coherent with the voice/opener fail-silent architecture (revised 2026-05-24; the original "extend the existing SessionStart hook" phrasing was written when only one SessionStart hook existed).

- Walk `docs/fellowship/` top level
- Flag any file or folder not in the canonical tree
- Surface one line: *"Drift detected — `<paths>` outside the contract."*

Notice only, no question. The user reacts if they want. This catches accumulated drift before it normalizes.
